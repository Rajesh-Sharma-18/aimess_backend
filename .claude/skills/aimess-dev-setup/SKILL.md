# AIMess dev setup

## Steps (order matters)

```bash
pnpm install
pnpm build:packages
```

Copy env files:

- Root: `.env.example` → `.env` (Docker Compose substitution)
- Each app: `apps/<service>/.env.example` → `.env` (gateway, auth, user, notifications, …)

```bash
pnpm docker:up           # postgres, mongo (single-node replSet rs0, auto-initiated by healthcheck), redis, rabbitmq, minio
pnpm db:generate         # prisma generate for auth + user + community
pnpm db:migrate:deploy   # prisma migrate deploy for auth then user (Postgres)
pnpm db:setup:community  # community (Mongo): db push schema + seed categories — NOT migrations
pnpm dev                 # all apps via Turbo
```

**community-service is Mongo (Prisma 6) — no migrations.** Each dev's Mongo volume starts empty, so seed data is NOT shared via git: every dev must run `pnpm db:setup:community` once (idempotent) or the category dropdown / community create will fail (no categories). `db:setup:community` = `db:push` (collections + indexes) + `db:seed` (10 categories). Mongo must be a replica set (the compose healthcheck runs `rs.initiate()` automatically on `docker:up`).

Per-app dev: `pnpm dev:gateway`, `pnpm dev:auth`, `pnpm dev:user`, or `pnpm --filter @aimess/notifications-service dev`.

## Common failures

| Error                                                                                                                                                    | Fix                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| -------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Cannot find package .../dist/index.js`                                                                                                                  | `pnpm build:packages` (shared packages compile to gitignored `dist/`)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| Turbo persistent task concurrency                                                                                                                        | `turbo.json` → `"concurrency": "15"`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| RabbitMQ `ACCESS_REFUSED` on Windows                                                                                                                     | Native Erlang already on 5672 — set `RABBITMQ_PORT=5673` in root `.env` and `RABBITMQ_URL=amqp://user:pass@localhost:5673` in app envs                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| Redis hangs / service can't reach Redis on Windows (TCP connects but never "ready"; e.g. auth-service blocks at boot, gateway shows `ECONNREFUSED 3001`) | A **native Windows Redis service** (`C:\Program Files (x86)\Redis\redis-server.exe`) is squatting on IPv4 `0.0.0.0:6379`, shadowing the Docker container (which only got IPv6 `::`). Check with PowerShell `Get-NetTCPConnection -LocalPort 6379 -State Listen`. Fix: **stop/disable the native service** (`Stop-Service Redis; Set-Service Redis -StartupType Disabled`) then `docker compose up -d redis`; OR move Docker Redis to a free port — `REDIS_PORT=6380` in root `.env` + each app `.env` — then `docker compose up -d redis`. (auth-service now boots anyway after a 5s Redis-connect timeout, but Redis-backed features stay broken until the port is fixed.) |
| Postgres init didn't create `aimess_*` DBs                                                                                                               | Keep `POSTGRES_DB=postgres` (or unset); the init script in `docker/postgres/init` only runs on first volume create                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| Prisma client missing after pull                                                                                                                         | `pnpm db:generate` (auth-service and user-service each have their own schema)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `notifications-service` can't send mail locally                                                                                                          | Run MailHog on SMTP 1025 (defaults match `.env.example`)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| MinIO presigned URLs fail                                                                                                                                | Create the bucket in the MinIO console (`localhost:9001`) matching `MINIO_BUCKET_AVATARS`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| community-service `P2031` "MongoDB needs a replica set" on any write/seed                                                                                | Prisma's Mongo connector wraps writes to `@unique`-indexed models in transactions → a replica set is mandatory. The local `mongodb` container runs as a **single-node replica set, no auth**: `command: ["mongod","--replSet","rs0","--bind_ip_all"]` + `rs.initiate()` (the healthcheck auto-initiates). After editing compose: `docker compose up -d --force-recreate mongodb`. Connection string is auth-less: `mongodb://localhost:27018/community_db?directConnection=true`.                                                                                                                                                                                           |
| community-service Prisma client errors `accelerateUrl/adapter required` or no Mongo support                                                              | **Prisma 7 dropped MongoDB.** community-service is pinned to **Prisma 6.x** with generator `provider="prisma-client-js"`, generated client imported from `src/generated/prisma/index.js`. auth/user stay on Prisma 7 (pnpm isolates per-package). Mongo `createMany` does NOT support `skipDuplicates`.                                                                                                                                                                                                                                                                                                                                                                     |
| community-service `typecheck` fails with `EPERM ... rename query_engine-windows.dll.node`                                                                | The `typecheck` script runs `prisma generate` first; on Windows it can't replace the Prisma 6 query-engine DLL while a node/tsx process holds it. NOT a TS error. Stop stray processes (`pkill -f "tsx watch"`) or run `pnpm --filter @aimess/community-service exec tsc --noEmit` directly (client is already generated).                                                                                                                                                                                                                                                                                                                                                  |
| Object storage / image uploads                                                                                                                           | Shared **`@aimess/storage`** package wraps all MinIO/S3 mechanics (presign upload/view, HEAD, delete, ensureBuckets, key-build, MIME/size validation). Each service has ONE generic `POST /<svc>/uploads/url` with a `type` (e.g. `AVATAR`, `COMMUNITY_AVATAR`) → bucket/prefix/limits registry in `config/uploads.ts`. Don't add per-resource upload endpoints or re-import `@aws-sdk/*` in a service.                                                                                                                                                                                                                                                                     |
